# Деплой

Прод — один VPS с docker compose. На сервер попадают два файла: `compose.prod.yaml` (как `~/spectra/compose.yaml`) и `.env`, который собирается из переменных и секретов GitHub при каждом деплое. Руками на сервере ничего не правится.

## Что работает на сервере

| Сервис | Что делает |
|---|---|
| `caddy` | образ `…/web` из `web/Dockerfile`, единственный, кто смотрит в интернет: TLS-сертификат Let's Encrypt для `SPECTRA_DOMAIN`, `/tracks…` и `/health` проксирует в api (`/ready` остаётся внутри: его спрашивает только healthcheck контейнера), всё остальное — веб-клиент со строгим CSP |
| `migrate` | при каждом старте: миграции Postgres, бакет в S3, группа воркеров в Redis; отработал и вышел |
| `api` | `spectra` в серверном режиме: принимает загрузки, отдаёт статусы, SSE и таймлайны; с Caddy его связывает внутренняя сеть `proxy`, выхода в интернет у него нет, хотя он разбирает чужие файлы |
| `worker` | `spectra-worker`: берёт задачи из Redis, анализирует, раз в час удаляет разборы, которые не открывали 30 дней |
| `postgres`, `redis`, `s3` | хранилища во внутренней сети без портов наружу и без выхода в интернет; у каждого контейнера свой лимит памяти и процессов |
| `prometheus` | раз в 15 секунд собирает метрики api и воркера с их порта 9100 внутри стека, хранит 15 дней |
| `grafana` | дашборд Spectra; слушает только `SPECTRA_GRAFANA_BIND_ADDRESS`, в интернет не смотрит |

Счётчики одновременных загрузок, потоков и таймлайнов живут в памяти процесса api, поэтому api должен оставаться одним процессом с одной репликой; иначе каждая реплика пропустит свою долю. Воркер раз в час переводит в `failed` разборы, о которых два часа не было новостей (например, api перезапустили посреди загрузки), чтобы они не занимали очередь.

`api` и `worker` стартуют только после успешного `migrate`. Healthcheck api — `GET /ready`: пока какое-то хранилище не отвечает, контейнер не считается здоровым, и `up --wait` ждёт.

## Как запускается

- Пуш тега `v*` (например, `git tag v0.1.0 && git push origin v0.1.0`) или ручной запуск workflow `deploy` в Actions на теге `v*`. С ветки workflow сразу останавливается, а окружение `production` (ниже) вообще не отдаёт ей секреты.
- Workflow собирает образы `ghcr.io/<владелец>/<репозиторий>:<коммит>` (движок) и `ghcr.io/<владелец>/<репозиторий>/web:<коммит>` (Caddy с веб-клиентом), кладёт файлы на сервер, делает `docker compose pull` и `up --wait`, затем `spectra-smoke` внутри контейнера api и `GET https://<домен>/health` снаружи.
- Откат — ручной запуск `deploy` на предыдущем теге. Миграции пока только добавляют, старый код с новой схемой работает.

## Сервер, один раз

1. Docker Engine 27 или новее с плагином compose: сеть `edge` включает IPv6, чтобы Caddy видел настоящие адреса IPv6-посетителей, а не адрес шлюза Docker (иначе все они делили бы один лимит загрузок).
2. Отдельный пользователь для деплоя в группе `docker`. Группа `docker` равна root на этой машине, поэтому ключ этого пользователя — только для деплоя.
3. SSH-ключ без пароля: публичная часть в `~/.ssh/authorized_keys` пользователя деплоя с опцией `restrict` в начале строки (`restrict ssh-ed25519 AAAA… deploy`: без проброса портов, агента и терминала), приватная — в секрет `DEPLOY_SSH_KEY`. Workflow удаляет ключ с раннера в конце, даже если деплой упал.
4. Ключи хоста — с консоли самого сервера, а не по сети: `for key in /etc/ssh/ssh_host_*_key.pub; do printf '<адрес сервера> %s\n' "$(cut -d' ' -f1,2 "$key")"; done` — вывод в секрет `DEPLOY_KNOWN_HOSTS`. `ssh-keyscan` по сети доверяет тому, кто ответил, а это может быть не ваш сервер.
5. DNS: A-запись (и AAAA, если есть IPv6) домена на адрес сервера. Без неё Caddy не получит сертификат.
6. Открыть в файрволе 80/tcp, 443/tcp и 443/udp (HTTP/3).
7. Если на сервере уже стоит nginx или другой прокси на 80/443 (как было при `SPECTRA_BIND_ADDRESS`), его надо убрать: теперь эти порты занимает Caddy, иначе `up` упадёт с «port is already allocated».

## GitHub, один раз

Settings → Environments → `production`:

- Deployment branches and tags → Selected branches and tags → правило для тегов `v*`. Без этого любой, у кого есть право записи, запустит деплой со своей ветки и прочитает секреты.
- Required reviewers → вы сами: каждый деплой ждёт подтверждения.
- Settings → Rules → Rulesets → новое правило для тегов `v*`: создавать, менять и удалять их может только владелец. Иначе ограничение по тегу обходится новым тегом.

Секреты:

| Имя | Что |
|---|---|
| `DEPLOY_SSH_KEY` | приватный ключ пользователя деплоя |
| `DEPLOY_KNOWN_HOSTS` | ключи хоста сервера, снятые с его консоли |
| `POSTGRES_PASSWORD` | пароль Postgres |
| `REDIS_PASSWORD` | пароль Redis |
| `S3_ACCESS_KEY` | ключ доступа versitygw |
| `S3_SECRET_KEY` | секрет versitygw |
| `GRAFANA_ADMIN_PASSWORD` | пароль пользователя `admin` в Grafana |

Переменные:

| Имя | Что |
|---|---|
| `DEPLOY_HOST` | адрес сервера |
| `DEPLOY_USER` | пользователь деплоя |
| `SPECTRA_DOMAIN` | домен сервиса, например `spectra.example.org` |
| `SPECTRA_HTTP_PORT` | `80`: нужен Let's Encrypt и для редиректа на HTTPS |
| `SPECTRA_HTTPS_PORT` | `443` |
| `SPECTRA_LOG_LEVEL` | необязательно, по умолчанию `info` |
| `SPECTRA_API_MEMORY_LIMIT` | необязательно, по умолчанию `2g` (так же ограничен `migrate`): загрузка в 256 МиБ на пике занимает в api около двух своих размеров (временный файл в tmpfs до 640 МиБ и сам файл), одновременно принимаются две |
| `SPECTRA_WORKER_MEMORY_LIMIT` | необязательно, по умолчанию `2g` |
| `SPECTRA_UPLOADS_PER_HOUR` | необязательно, по умолчанию `20`: загрузок за последний час с одного адреса (IPv4 или сети IPv6 /64) |
| `SPECTRA_NETWORK_UPLOADS_PER_HOUR` | необязательно, по умолчанию `60`: с одной сети IPv6 /48 |
| `SPECTRA_TOTAL_UPLOADS_PER_HOUR` | необязательно, по умолчанию `600`: со всего мира вместе |
| `SPECTRA_GRAFANA_BIND_ADDRESS` | `127.0.0.1`: Grafana открывается через SSH-туннель |
| `SPECTRA_GRAFANA_PORT` | порт Grafana на сервере, например `3000` |
| `SPECTRA_METRICS_RETENTION` | необязательно, по умолчанию `15d`: сколько Prometheus хранит метрики |

`SPECTRA_BIND_ADDRESS` и `SPECTRA_API_PORT` больше не нужны: api наружу не публикуется, их можно удалить из environment.

Значения без одинарных кавычек и переводов строк. Пароли и ключи удобно генерировать так: `openssl rand -hex 32`.

## Настройки движка

Compose задаёт их сам, перечислены для запуска без compose.

| Переменная | По умолчанию | Что |
|---|---|---|
| `SPECTRA_MODE` | `local` | `local` — всё в памяти, воркер внутри api; `hosted` — Postgres, Redis, S3 и отдельный `spectra-worker` |
| `SPECTRA_POSTGRES_HOST`, `_PORT`, `_DATABASE`, `_USER`, `_PASSWORD` | —, `5432`, `spectra`, `spectra`, — | Postgres |
| `SPECTRA_REDIS_HOST`, `_PORT`, `_DATABASE`, `_PASSWORD` | —, `6379`, `0`, нет | Redis |
| `SPECTRA_S3_URL`, `_REGION`, `_ACCESS_KEY`, `_SECRET_KEY`, `_BUCKET` | —, `us-east-1`, —, —, `spectra` | S3 |
| `SPECTRA_RETENTION_DAYS` | `30` | сколько дней хранить разбор после последнего открытия |
| `SPECTRA_SWEEP_INTERVAL_S` | `3600` | как часто воркер ищет устаревшие разборы |
| `SPECTRA_UPLOADS_PER_HOUR` | `20` | загрузок за последний час (окно скользит) с одного адреса: IPv4 или сети IPv6 /64; сверх — `429 rate_limited` |
| `SPECTRA_NETWORK_UPLOADS_PER_HOUR` | `60` | то же для сети IPv6 /48, чтобы блок из туннельного брокера не давал тысячи отдельных лимитов |
| `SPECTRA_TOTAL_UPLOADS_PER_HOUR` | `600` | то же для всех вместе |
| `SPECTRA_MAX_UPLOAD_BYTES` | `268435456` | размер файла, сверх — `413 file_too_large`; Caddy режет тело на 257 МиБ |
| `SPECTRA_MAX_DURATION_S` | `1800` | длительность трека |
| `SPECTRA_MAX_DECODED_SAMPLES` | `345600000` | длительность × частота × каналы: 30 минут стерео 96 кГц; сверх — `413`. Частота выше 192 кГц и больше 8 каналов — `415` |
| `SPECTRA_MAX_PENDING_ANALYSES` | `4` | треков в очереди и в работе, сверх — `503 busy` |
| `SPECTRA_MAX_CONCURRENT_UPLOADS` | `2` | загрузок одновременно на весь api, лишняя сразу получает `503 busy`; с одного адреса и одной сети /48 — по одной, вторая получает `429`. Ни то ни другое не тратит часовой лимит |
| `SPECTRA_MIN_UPLOAD_BYTES_PER_S` | `65536` | после 30 секунд тело загрузки должно приходить не медленнее, и без пауз дольше 30 секунд, иначе `400 no_file` |
| `SPECTRA_MAX_UPLOAD_S` | `600` | за сколько секунд должно прийти всё тело загрузки, иначе `400 no_file`. Две одновременные загрузки на весь api — узкое место: два адреса из разных сетей, загружающие большие файлы честно, но медленно, займут оба места на эти 10 минут |
| `SPECTRA_MAX_EVENT_STREAMS` | `64` | открытых потоков SSE на весь api, сверх — `503 busy`; столько же соединений у отдельного пула Redis для подписок |
| `SPECTRA_MAX_EVENT_STREAMS_PER_ADDRESS` | `4` | потоков SSE с одного адреса, сверх — `429`; клиент тогда спрашивает статус трека и переподключается |
| `SPECTRA_MAX_EVENT_STREAMS_PER_NETWORK` | `8` | то же для сети IPv6 /48 |
| `SPECTRA_EVENT_STREAM_LIFETIME_S` | `300` | сколько живёт поток SSE, потом браузер переподключается |
| `SPECTRA_MAX_TIMELINE_DOWNLOADS` | `16` | таймлайнов, отдаваемых одновременно, сверх — `503 busy`; одному адресу — 2, сети /48 — 4, сверх — `429`. Кто не дочитал таймлайн за 5 минут, теряет соединение |
| `SPECTRA_LOG_FORMAT` | `text` | `json` — одна строка JSON на запись; в проде включено |
| `SPECTRA_METRICS_PORT` | нет | порт `/metrics` для Prometheus; в compose `9100`, наружу не публикуется |
| `SPECTRA_FORWARDED_ALLOW_IPS` | `127.0.0.1` | от каких прокси верить `X-Forwarded-For`; в проде `*`, потому что api доступен только через Caddy, а Caddy отбрасывает присланный клиентом заголовок |

Прочерк — значение обязательно в серверном режиме.

## Метрики и Grafana

С компьютера: `ssh -L 3000:127.0.0.1:<SPECTRA_GRAFANA_PORT> <пользователь>@<сервер>`, потом http://localhost:3000, вход `admin` и `GRAFANA_ADMIN_PASSWORD`. Дашборд Spectra открывается сразу: загрузки и анализы в минуту, время анализа (p50, p95), очередь, время ответа по маршрутам, ошибки и `429`, память api и воркера, удалённые за сутки разборы.

Дашборд и источник данных задаются в `compose.prod.yaml` (раздел `configs`) и перезаписываются при каждом деплое: правки в интерфейсе Grafana не сохраняются, меняйте JSON в репозитории. В выражениях там `$$` вместо `$`, иначе compose примет их за свои переменные.

Логи — `docker compose logs api worker`, по строке JSON на запись.

## Веб-клиент локально

Движок на `127.0.0.1:8000` (`uv run spectra`), потом в `web/`: `npm ci`, `npm run dev`. Vite проксирует `/tracks` и `/health` на движок (`SPECTRA_ENGINE_URL`, если он на другом адресе), так что клиент, как и в проде, ходит только на свой адрес. Перед коммитом — `npm run check`.

## Локально весь стек

`cp .env.example .env`, поменять пароли, `docker compose up --build --wait`. Api на `SPECTRA_BIND_ADDRESS:SPECTRA_API_PORT`, без Caddy и TLS. `spectra-smoke http://127.0.0.1:8000` проверяет весь путь от загрузки до таймлайна.

## Что важно знать

- Бэкапов нет: Postgres и S3 хранят только кэш разборов на 30 дней. Если том пропадёт, пользователи загрузят треки заново, а `migrate` при следующем деплое создаст схему, бакет и группу воркеров с нуля.
- Docker публикует порты в обход файрвола хоста (в том числе ufw). Наружу открыт только Caddy; не добавляйте `ports` хранилищам. `SPECTRA_GRAFANA_BIND_ADDRESS=0.0.0.0` откроет Grafana в интернет.
- Postgres берёт пароль только при первом создании тома. Смена секрета потом не меняет пароль в базе: сначала `ALTER ROLE spectra PASSWORD ...` в базе, потом секрет.
- Grafana, как и Postgres, берёт `GRAFANA_ADMIN_PASSWORD` только при первом создании тома `grafana`. Потом пароль меняется в самой Grafana или `docker compose exec grafana grafana cli admin reset-admin-password <новый>`.
- Api верит `X-Forwarded-For` от любого соседа (`SPECTRA_FORWARDED_ALLOW_IPS=*`): это безопасно, пока перед api только Caddy, который заменяет заголовок клиента. Если поставить перед Caddy CDN или включить в нём `trusted_proxies`, лимит загрузок придётся пересмотреть.
- Сертификаты Caddy лежат в томе `caddy-data`. Не удаляйте его без нужды: у Let's Encrypt лимиты на выпуск.
- Задача, на которой воркер упал или был убит, перезапущенный воркер подхватывает сразу, другой воркер — через 5 минут. Загрузка удаляется только после того, как результат записан, поэтому перезапуск ничего не теряет. После трёх попыток трек помечается ошибкой `internal`, чтобы один «ядовитый» файл не ронял воркер бесконечно.
- Образ в GHCR по умолчанию приватный; сервер логинится в реестр коротким токеном задачи деплоя.
